## Goal

Allow downstream consumers of the `mewt` library to specify a custom version string when calling `run_main`, so the CLI `--version` output reflects the consumer's own version rather than mewt's crate version.

## Context

`run_main` in `src/core/main_shared.rs` currently accepts:
- `registry: Arc<LanguageRegistry>`
- `namespace: &str`
- `description: &str`

Clap picks up the version automatically from `CARGO_PKG_VERSION` at compile time (mewt's own version). When a consumer crate wraps `run_main`, their binary will advertise mewt's version, not their own.

## Proposed Solution

Add an optional `version` parameter to `run_main`, e.g.:

```rust
pub async fn run_main(
    registry: Arc<LanguageRegistry>,
    namespace: &str,
    description: &str,
    version: Option<&str>,   // <-- new
) -> AppResult<()> {
```

Then apply it to the clap `Command`:

```rust
let mut cmd = Args::command();
cmd = cmd.name(namespace_static).about(description_static);
if let Some(ver) = version {
    let ver_static: &'static str = Box::leak(ver.to_string().into_boxed_str());
    cmd = cmd.version(ver_static);
}
let matches = cmd.get_matches();
```

Update the internal `main.rs` caller to pass `None` (keeping existing behaviour):

```rust
run_main(Arc::new(registry), "mewt", "Mutation testing framework", None).await?;
```

## Files to Change

- `src/core/main_shared.rs` — add `version` param and apply to clap command
- `src/main.rs` — pass `None` as new arg
- `src/lib.rs` — ensure `run_main` re-export signature stays in sync
