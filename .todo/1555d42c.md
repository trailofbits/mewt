## Problem

Build times were 7-10 minutes for back-to-back `just build` commands without source changes. Initial diagnosis suggested sqlx was the problem, but the real issue was deeper.

## Root Cause

**Cargo assigns different `OUT_DIR` paths to different build "flavors":**
- `cargo sqlx prepare` (check flavor) → `target/debug/build/mewt-507750b6319afeca/out/`
- `cargo build` (build flavor) → `target/debug/build/mewt-2a284f04bb0db85e/out/`

The **cc crate caches compiled `.o` files inside `OUT_DIR`**. Each build flavor gets an empty cache, so tree-sitter grammars (6 × 900ms = ~5s) recompile every time a different flavor runs, even though the C source code is identical.

`cargo:rerun-if-changed` prevents unnecessary build script runs but can't help cc's per-`OUT_DIR` caching limitation.

## Solution: Persistent Grammar Cache

Created `target/.grammar-cache/` to store compiled grammar `.a` files (5.5MB) in a flavor-agnostic location:

```rust
// build.rs checks cache before compiling
let cached_lib = cache_dir.join(format!("lib{}.a", lib_name));
if cached_lib.exists() && cached_lib.modified() > source.modified() {
    // Copy cached .a to OUT_DIR (instant)
    fs::copy(&cached_lib, out_dir.join(format!("lib{}.a", lib_name)))?;
} else {
    // Compile C code and update cache (~900ms per grammar)
    cc::Build::new()...compile(lib_name);
    fs::copy(out_dir.join(...), &cached_lib)?;
}
```

**Cache persists across:**
- ✅ Build flavors (check vs build vs test)
- ✅ `cargo clean -p mewt` 
- ❌ Full `cargo clean` (intentional - forces clean slate)

## Results

| Action | Before | After |
|--------|--------|-------|
| Back-to-back `just build` | 7-10 min | ~2s |
| `cargo clean -p mewt && build` | ~10s | ~5s |
| Touch `src/*.rs` | N/A | ~2s |
| Touch `grammars/*/parser.c` | N/A | ~5s |

**Key:** After `just init-db` (sqlx flavor), subsequent `cargo build` now takes 2.27s instead of 6.91s because grammars aren't recompiled.

## Rejected Approaches

- **Remove `init-db` from build flow:** Fixes symptom but doesn't solve root cause of cross-flavor recompilation
- **Just `cargo:rerun-if-changed`:** Prevents build script runs but cc still recompiles in empty `OUT_DIR`
- **Trust cc's native cache:** Only works within a single build flavor; breaks across check/build/test

## Files Modified

- `build.rs`: Added timestamp-based cache checking and `.a` file persistence
- `justfile`: Made `cargo sqlx prepare` conditional with `--check` flag to avoid regenerating `.sqlx/*.json`

## Key Insight

Third-party deps like serde share `.rmeta` files in `target/debug/deps/` across all build flavors, but build script outputs are isolated per-`OUT_DIR`. The persistent cache bridges this gap for static C libraries that don't vary by flavor.
