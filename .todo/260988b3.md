## Problem

There's an inconsistency between `run` and `mutate` commands regarding target arguments:

- **`run` command**: Targets are optional. If not provided, it tests existing mutants in the database. If config `[targets].include` is set, it can be used for mutation generation.
  
- **`mutate` command**: Targets are **required** (`required = true` in CLI definition). Users must provide positional target arguments even if `[targets].include` is set in config file.

## Expected Behavior

Both commands should be consistent:
1. Users should be able to run `mewt mutate` with just config file settings (`[targets].include` and `[targets].ignore`)
2. CLI positional arguments should be optional and override config when provided
3. If neither CLI args nor config targets are set, show an error

## Implementation

1. Remove `required = true` from `MutateArgs.targets` in `src/core/cli.rs`
2. Update help text to clarify optional nature and fallback behavior
3. No changes needed to `main_shared.rs` - existing `resolve_targets()` handles validation

## Solution Summary

✅ **COMPLETED**

Changed `src/core/cli.rs`:
- Removed `required = true` from `MutateArgs.targets` field
- Updated help text to match `RunArgs` style: "If not provided, uses config [targets].include."

The existing `resolve_targets()` function already handles:
- CLI targets take precedence when provided
- Falls back to config `[targets].include` when CLI is empty
- Returns error when both are empty with clear message
