# Design: Move command-specific flags out of global Args

## Problem
The `--mutations` flag is currently global but only applies to the `run` command. Similarly, `--ignore-targets`, `--test.cmd`, and `--test.timeout` are global but only used by specific commands. This clutters `mewt --help` with flags that don't apply to all commands.

## Design Decisions

### 1. Semantic Config Grouping (not command-based)
Organize config by **concern/feature**, not by command:

```toml
# Root level: Universal options
db = ".mewt/mewt.db"

[log]
# Logging feature (applies to all commands)
level = "info"
color = "auto"

[test]
# Test EXECUTION feature (shared by run, test commands)
cmd = "cargo test"
timeout = 30

[[test.per_target]]
glob = "**/*.rs"
cmd = "cargo test --lib"

[run]
# Run-specific options
ignore_targets = ["vendor/", "node_modules/"]
mutations = ["ER", "CR", "BR"]
comprehensive = false

[mutate]
# Mutate-specific options
ignore_targets = ["vendor/", "node_modules/"]
```

**Rationale**: `[test]` is shared config for test execution, not "test command config". This allows natural sharing between commands (run and test both use test execution config).

### 2. CLI Flag Placement
Move flags from global to command-specific structs (remove `global = true`):

**Truly Global** (applies to ALL commands):
- `--cwd` - working directory
- `--db` - database location
- `--log.level` - logging level
- `--log.color` - logging color

**Command-Specific**:
- `--ignore-targets` → `RunArgs`, `MutateArgs`
- `--mutations` → `RunArgs` only
- `--test.cmd` → `RunArgs`, `TestArgs`
- `--test.timeout` → `RunArgs`, `TestArgs`

### 3. Resolution Order
For command-specific options: CLI flag > Config file > Default

```rust
// Example for run command
let mutations = run_args.mutations
    .or_else(|| config().run()?.mutations().map(|v| v.join(",")));

let test_cmd = run_args.test_cmd
    .or_else(|| config().test()?.cmd().map(String::from));
```

### 4. Help Text Result
- `mewt --help` - Only shows db, cwd, log.* flags
- `mewt run --help` - Shows run-specific + global flags
- `mewt results --help` - Shows results-specific + global flags
- No cross-contamination of command-specific flags

### 5. Config Availability
All config sections are loaded once and available to all commands, but each command only reads what it needs. This is fine - no performance impact, enables sharing.

## Important Discovery: ignore_targets Usage

The `ignore_targets` config is used by `is_path_excluded()` in `src/core/types/config.rs`, which is called from `Target::load_targets()`. This function is used by BOTH:
- `run` command (via execute_run)
- `mutate` command (via execute_mutate)

### Decision Point: Where should ignore_targets live?

**Option A: Keep at root level (simplest)**
- Remains global config
- No changes needed to is_path_excluded() or load_targets()
- Used by both run and mutate without duplication
- ✅ Simplest implementation
- ❌ Still appears in global CLI flags

**Option B: Pass as parameter to load_targets()**
- Move to [run] and [mutate] sections separately
- Change signature: `load_targets(path, store, registry, ignore_patterns: Option<&[String]>)`
- Each command resolves from its own config section
- ✅ True command-specific config
- ❌ More invasive changes
- ❌ Duplication in config file if settings are the same

**Option C: Create [targets] or [discovery] section**
- Semantic grouping: target discovery concerns
- Shared by all commands that discover targets
- Similar to how [test] is shared
- ✅ Clear semantics
- ✅ No duplication
- ✅ Can add other discovery options later
- ❌ Slightly more config structure

**RECOMMENDATION: Option A (simplest) or Option C (most semantic)**

Option A keeps the current behavior with minimal changes. Option C is more "correct" semantically but adds another config section. Since ignore_targets is truly about target discovery (not command-specific), Option C might be better long-term.

For now, proceed with **Option A** to minimize changes, but note that ignore_targets could move to [targets] section in a future refactor if we add more target-discovery options.
