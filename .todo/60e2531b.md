## Objective

Replace the `--cwd` flag with a `--config` flag that points to the config file. The directory where that config file lives should act as the current working directory.

## Implementation Summary

Successfully replaced `--cwd` with `--config` flag and **ensured working directory is ALWAYS set to config file's parent**, regardless of discovery method.

### Key Changes

#### 1. CLI Arguments (src/core/cli.rs)
- Removed `cwd` field from `Args` struct
- Added `config` field that accepts an optional path to the config file
- Updated help text to explain the working directory behavior

#### 2. Configuration Module (src/core/types/config.rs)
- Added `CONFIG_PATH` static variable to store explicit config file path
- Added `set_config_path()` and `get_config_path()` functions
- Made `find_nearest_config_file()` public for use in main
- Updated `init_with_overrides()` to use the config path that was already discovered and set by main
- Fixed `find_nearest_config_file()` to safely handle cases where config filename isn't set (e.g., in tests)

#### 3. Main Logic (src/core/main_shared.rs)
- **Critical fix**: Config file discovery and cwd change happen together, whether config is:
  - Explicitly specified via `--config` flag, OR
  - Auto-discovered by walking up from current directory
- Added validation to ensure config path is a file
- Implemented logic to ALWAYS set working directory to config file's parent directory
- Stored the config path for use during config initialization

#### 4. Documentation (README.md)
- Updated configuration sources section to mention `--config` flag
- Updated config file discovery explanation to describe both explicit and automatic discovery modes
- Clarified that working directory is set to config file's parent in both cases
- **Fixed config file example** to match actual Config struct (db at top level, not in [general] section)

## Behavior

### The Fix: Consistent Path Resolution

**Both methods now behave identically:**

```bash
# Method 1: Explicit config
cd /anywhere
mewt --config /project/mewt.toml run
# → cwd set to /project/
# → db at /project/mewt.sqlite ✓

# Method 2: Auto-discovery
cd /project/src/deeply/nested
mewt run
# → finds /project/mewt.toml
# → cwd set to /project/
# → db at /project/mewt.sqlite ✓
```

### Why This Matters

If config says `db = "./foo/bar.db"`, it ALWAYS resolves relative to the config file's location, not the user's cwd. This ensures:
- Predictable behavior
- Config files are portable
- Follows common conventions (Cargo.toml, package.json, etc.)

## Breaking Change

This is a breaking change for users who were using the `--cwd` flag. However:
- The `--cwd` flag was not documented in examples
- Migration is straightforward: `--cwd /path --config config.toml` becomes `--config /path/config.toml`
- The new behavior is more intuitive and follows common conventions
