## Problem

Currently, the `--mutation-type` filter only accepts a single mutation slug. This is limiting when users want to filter by multiple mutation types at once. For example, to see both Expression Replacements (ER) and Condition Reversals (CR), users would need to run separate commands.

## Current Usage

```bash
# Can only filter by one type at a time
mewt results --mutation-type ER
mewt print mutants --mutation-type CR
```

## Expected Behavior

Rename to `--mutation-types` (plural) and accept a comma-separated list:

```bash
# Filter by multiple mutation types
mewt results --mutation-types ER,CR,BR
mewt print mutants --mutation-types ER,LR

# Still works with single value
mewt results --mutation-types ER
```

## CSV Parsing Utility

The `parse_csv` utility is in `src/core/utils.rs`:
```rust
pub fn parse_csv<T>(csv_str: Option<&str>) -> Option<Vec<T>>
where
    T: FromStr,
{
    csv_str.map(|s| {
        s.split(',')
            .filter_map(|part| {
                let trimmed = part.trim();
                if trimmed.is_empty() {
                    None
                } else {
                    T::from_str(trimmed).ok()
                }
            })
            .collect()
    })
}
```

**Benefits:**
- Automatic trimming and empty value filtering
- Invalid values silently filtered (graceful degradation)
- Returns `None` if input is `None`
- Returns `Some(Vec<T>)` with valid parsed values
- Well-tested with 8 test cases

## Backward Compatibility

This is a breaking change since the flag name changes. Consider:

1. **Option A**: Just rename (simplest, clean break)
2. **Option B**: Add deprecated alias that warns:
   ```rust
   #[clap(long, hide = true)]
   #[deprecated(note = "Use --mutation-types instead")]
   pub mutation_type: Option<String>,
   ```
   Then check both flags and warn if old one is used.

**Recommendation:** Option A (clean break) - the tool is pre-1.0 and this makes the API more consistent.
