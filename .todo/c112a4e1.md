## Problem

Currently, the `--mutation-type` filter only accepts a single mutation slug. This is limiting when users want to filter by multiple mutation types at once. For example, to see both Expression Replacements (ER) and Condition Reversals (CR), users would need to run separate commands.

## Solution Implemented ✅

Successfully renamed `--mutation-type` to `--mutation-types` (plural) and added CSV list support across the entire codebase.

### Changes Made

1. **CLI Layer** (`src/core/cli.rs`)
   - Renamed `mutation_type` → `mutation_types` in `ResultsArgs` and `PrintMutantsArgs`
   - Updated help text to indicate "comma-separated, e.g., 'ER,CR,BR'"
   - Added `value_name = "SLUGS"` for better CLI UX

2. **Filter Structs**
   - `ResultsFilters` in `src/core/cmds/results.rs`
   - `MutantsFilters` in `src/core/cmds/print.rs`

3. **Command Layer** 
   - `src/core/cmds/results.rs`: Added CSV parsing with `parse_csv::<String>(filters.mutation_types.as_deref())`
   - `src/core/cmds/print/mutants.rs`: Added CSV parsing
   - `src/core/main_shared.rs`: Updated struct instantiation to use new field names

4. **Store Layer** (`src/core/store.rs`)
   - Updated `get_outcomes_filtered()` signature: `mutation_type: Option<String>` → `mutation_types: Option<Vec<String>>`
   - Updated `get_mutants_filtered()` signature: `mutation_type: Option<String>` → `mutation_types: Option<Vec<String>>`
   - Implemented SQL IN clause for filtering by multiple mutation types:
     ```rust
     if let Some(mutation_slugs) = mutation_types {
         if !mutation_slugs.is_empty() {
             add_separator(&mut query_builder, &mut has_where);
             query_builder.push("m.mutation_slug IN (");
             let mut separated = query_builder.separated(", ");
             for slug in mutation_slugs {
                 separated.push_bind(slug);
             }
             query_builder.push(")");
         }
     }
     ```

### Usage Examples

```bash
# Filter by single mutation type
mewt results --mutation-types ER

# Filter by multiple mutation types
mewt results --mutation-types ER,CR,BR
mewt print mutants --mutation-types ER,LR

# With spaces (automatically trimmed)
mewt results --mutation-types "ER, CR, BR"
```

## Implementation Details

- Uses the existing `parse_csv<T>` utility from `src/core/utils.rs`
- Automatic trimming and empty value filtering
- Returns `Option<Vec<String>>` ready for store layer
- Consistent with `--severity` and other CSV-based filters
- SQL IN clause provides efficient multi-value filtering at database level

## Breaking Change Note

This is a breaking change as the flag name changes from singular `--mutation-type` to plural `--mutation-types`. This is acceptable as the tool is pre-1.0 and improves API consistency.
