## Problem

`mewt print targets` currently only shows targets that are already in the database. It doesn't help users understand:
- What files would be included if they ran `mewt mutate`
- Whether their ignore patterns are working correctly
- Whether they have orphaned targets in DB that are excluded by config
- Whether targets are stale (file changed since mutation)

The output is also multi-line per target and shows the full hash on its own line, making it hard to scan.

## Expected Behavior

Show comprehensive one-line-per-target output with three boolean columns that clearly indicate state:

### Three Boolean Columns

- **In DB**: Is there a database entry for this target (with this hash)?
- **On Disk**: Does a file exist at this path with this hash?
- **Included**: Is this path included by current config (regardless of DB/disk state)?

**Important:** "Included" is ALWAYS checked against current config, even for deleted files. This helps users understand whether orphaned DB entries would be re-picked-up if files were restored, and whether to purge them.

### Table Format

```
In DB | On Disk | Included | Hash     | Path                | Mutants
------|---------|----------|----------|---------------------|---------
Yes   | Yes     | Yes      | a1b2c3d4 | src/runner.rs       | 123
Yes   | No      | Yes      | e5f6g7h8 | src/config.rs       | 45       ← old version
No    | Yes     | Yes      | f1e2d3c4 | src/config.rs       | -        ← new version (file changed)
Yes   | Yes     | No       | 12345678 | node_modules/x.js   | 5        ← orphaned by config
No    | Yes     | Yes      | 9a8b7c6d | src/new.rs          | -        ← pending mutation
Yes   | No      | Yes      | deadbeef | src/deleted.rs      | 10       ← deleted from disk
Yes   | No      | No       | cafebabe | test/ignored.rs     | 3        ← deleted + excluded
```

**Key insights:**
- A changed file appears as TWO rows (same path, different hashes)
- Hash column (8 chars) is needed to differentiate multiple rows with same path
- Language column removed (implied by file extension)
- Boolean columns are self-documenting - no need to memorize status words

### Color Coding (table format)
- Green: `Yes | Yes | Yes` (perfect state)
- Yellow: `Yes | No | Yes` (deleted but would be picked up if restored)
- Red: `Yes | No | No` (orphaned, safe to purge)
- Cyan: `No | Yes | Yes` (ready to mutate)
- Gray/Dim: Any row with `Included = No` (excluded by config)

## Implementation

1. **Gather all unique (path, hash) combinations:**
   - From DB: `store.get_all_targets()` → collect (path, hash, target)
   - From filesystem: Walk config include patterns, compute hash for each file → collect (path, hash, None)
   - Deduplicate by (path, hash) tuple

2. **For each unique (path, hash):**
   ```rust
   struct TargetRow {
       in_db: bool,         // Is (path, hash) in DB?
       on_disk: bool,       // Does file at path exist with this hash?
       included: bool,      // Is path included by current config?
       hash: String,        // First 8 chars
       path: PathBuf,
       mutants: Option<i64>, // Count from DB, or None
   }
   
   fn compute_row(path: &Path, hash: &Hash, db_target: Option<&Target>) -> TargetRow {
       let in_db = db_target.is_some();
       
       let on_disk = if path.exists() {
           match fs::read_to_string(path) {
               Ok(content) => Hash::digest(content) == *hash,
               Err(_) => false,
           }
       } else {
           false
       };
       
       let included = config().path_is_included(path); // Check against current config
       
       let mutants = if let Some(target) = db_target {
           Some(store.count_mutants(target.id).await?)
       } else {
           None
       };
       
       TargetRow {
           in_db,
           on_disk,
           included,
           hash: hash.to_hex()[..8].to_string(),
           path: path.to_path_buf(),
           mutants,
       }
   }
   ```

3. **For files on disk but not in DB:**
   - Compute hash from disk content to populate the Hash column
   - This is how we get the "new version" row when a file changes

4. **Format output:**
   - Use `comfy-table` for table format
   - Use console/style for colors based on boolean combination
   - Sort by path, then by in_db (Yes before No) to show old versions first
   - `-` in Mutants column when not in DB

5. **JSON format:**
   Add boolean fields to JSON output for programmatic access

## Files to Change

- `src/core/cmds/print/targets.rs` - Main implementation
- `src/core/types/config.rs` - Add `path_is_included(&Path) -> bool` helper method
- `src/core/store.rs` - Maybe add `count_mutants(target_id) -> i64` helper

## Edge Cases

- What if include pattern is empty/not set? (should match nothing, forcing explicit config)
- What about symlinks? (follow them - `fs::read_to_string` will follow)
- Large number of pending files? (might want to add `--only-db` flag to skip filesystem scan)
- Hash collision? (astronomically unlikely with SHA256)

## Benefits

- **Self-documenting:** Boolean columns are immediately clear, no need to memorize status words
- **File changes are explicit:** Two rows make it obvious when a file has changed
- **Config verification:** Easily see if ignore patterns are working
- **Orphan detection:** Quickly spot `In DB=Yes, Included=No` rows to purge
- **Pre-flight check:** See exactly what `mewt mutate` would pick up
- **One line per (path, hash):** Much easier to scan than multi-line output
