## Problem

`mewt print targets` currently only shows targets that are already in the database. It doesn't help users understand:
- What files would be included if they ran `mewt mutate`
- Whether their ignore patterns are working correctly
- Whether they have orphaned targets in DB that are excluded by config
- Whether targets are stale (file changed since mutation)

The output is also multi-line per target and shows the full hash on its own line, making it hard to scan.

## Solution Implemented

Implemented comprehensive one-line-per-target output with three boolean columns and optimized column ordering:

### Three Boolean Columns

- **In DB**: Is there a database entry for this target (with this hash)?
- **On Disk**: Does a file exist at this path with this hash?
- **Included**: Is this path included by current config (regardless of DB/disk state)?

### Column Order and Widths

Columns are ordered as: `In DB | On Disk | Included | Mutants | Hash | Path`

- **In DB**: 5 chars (exact fit for header)
- **On Disk**: 7 chars (exact fit for header)
- **Included**: 8 chars (exact fit for header)
- **Mutants**: 7 chars (accommodates large counts)
- **Hash**: 8 chars (8-character hash prefix)
- **Path**: Variable width (last column, doesn't shift other columns)

The path column is **last** so that variable-length paths don't shift subsequent columns around, making visual column scanning easier.

### Example Output

```
In DB | On Disk | Included | Mutants | Hash     | Path
------------------------------------------------------------------------------------------
Yes   | Yes     | Yes      | 22      | a7d67691 | src/core/cmds/clean.rs         ← Green (perfect)
Yes   | No      | Yes      | 4       | 54c25461 | src/core/cli.rs                ← Red (deleted)
No    | Yes     | Yes      | -       | fe0aad6c | src/core/cli.rs                ← Yellow (new version)
Yes   | Yes     | No       | 58      | 34228715 | tests/go/examples/hello-world.go ← Dim (excluded)
```

### Color Coding

- **Green**: `Yes | Yes | Yes` (perfect state - in DB, on disk, included)
- **Red**: `Yes | No | Yes` or `Yes | No | No` (deleted from disk or orphaned)
- **Yellow**: `No | Yes | Yes` (new version ready to mutate)
- **Gray/Dim**: Any row with `Included = No` (excluded by config)

## Implementation Details

1. **Added `path_is_included()` helper** to `src/core/types/config.rs` that checks if a path is included by current config patterns using globset matching and ignore pattern exclusion.

2. **Modified `src/core/cmds/print/targets.rs`** to:
   - Gather all unique (path, hash) combinations from both DB and filesystem
   - Use a composite string key `"path|hash"` for deduplication
   - Check each file's on-disk status and config inclusion status
   - Sort by path, then by in_db (DB entries first) to show old versions before new
   - Display in table format with boolean columns in optimal order
   - Apply color coding: green=perfect, red=deleted/orphaned, yellow=new version, dim=excluded
   - Path column is last to accommodate variable-length paths
   - Column widths optimized to exact header widths (5, 7, 8 for booleans)

3. **Updated `src/core/cmds/print.rs`** to pass the `LanguageRegistry` to the targets execute function (needed for filesystem scanning).

4. **JSON format** also updated to include the three boolean fields for programmatic access.

## Benefits

- **Self-documenting:** Boolean columns are immediately clear
- **File changes are explicit:** Two rows (old and new hash) make changes obvious
- **Config verification:** Easily see if ignore patterns are working
- **Orphan detection:** Quickly spot `In DB=Yes, Included=No` rows to purge
- **Pre-flight check:** See exactly what `mewt mutate` would pick up
- **One line per (path, hash):** Much easier to scan than multi-line output
- **Visual column scanning:** Path column is last, preventing shifts in fixed-width columns
- **Compact display:** Minimal column widths reduce wasted space

## Testing

- All existing tests pass
- Manual testing shows correct output for various scenarios:
  - Files in DB matching disk (perfect state) - Green
  - Files in DB that have changed on disk (shows both versions) - Red for old, Yellow for new
  - Files in DB but deleted from disk - Red
  - Files on disk but not in DB (ready to mutate) - Yellow
  - Files excluded by config patterns - Dim
- Pre-commit checks pass (fmt, check, lint, typos)
- Colors verified manually in terminal
- Column alignment verified with various path lengths
